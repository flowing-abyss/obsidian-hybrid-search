# Frozen quiet initial-index protocol

This note supersedes the initial-index acceptance conclusion in `final-performance-acceptance-review.md`. **Overall performance acceptance is pending.** The final repeated initial medians are descriptive but not adequate acceptance evidence because independent review mapped other-project load asymmetrically onto original measured trials 1 and 2. The raw data, favorable median, adverse exact-final single pair, and disclosed short-operation costs remain unchanged. No earlier result will be pooled into this repeat.

The root approved these rules before execution. `measure-initial-quiet.mjs` is an ignored acceptance collector only; it changes no package/runtime source or performance threshold.

- Run the exact frozen original and candidate packages, Node, actual E5 model, corpus, environment, database invariants, resource sampling, and cleanup helpers already used in the final audit. Assert package hashes before and after the run and archive the collector and helpers with a unique run label.
- A separate asynchronous host sample runs every second. Ownership starts at this collector's PID and follows actual process parentage. Its benchmark and helper descendants are excluded from external CPU. The root agent, sibling work, and unrelated processes are never excluded merely by matching a project path or executable name. Host records retain process IDs, parent IDs, CPU, RSS, safe program labels, and ownership flags, without full command lines or environment variables.
- Require 30 seconds of sampled quiet before each individual index. A sample is contaminated when any external process has CPU **>=20%**, or aggregate external CPU is **>=50%**. A sample error, invalid CPU inventory, or coverage gap **>3 seconds** makes the window ineligible. These conservative operational criteria are fixed independently of measured latency; macOS `ps` CPU percentages are sampled indicators, not proof that all transient contention or thermal differences are absent.
- Complete one excluded warmup pair, then three eligible measured pairs in fixed order **AB, BA, AB** (A=original, B=candidate). If either measured leg is contaminated, reject the entire pair and retry that same order slot. Keep every complete or partial attempt, original timing/resource/health records, sample references, and eligibility reasons. A functional or cleanup failure fails the run; it is not a noise exclusion.
- Stop after six measured attempts or 45 minutes, including admission/warmup time. Reaching the bound without three eligible measured pairs leaves the result pending. Cleanup may require the existing bounded child-stop grace period. No thresholds or eligibility rules are changed after seeing outcomes, and no retry is requested because of a slow but eligible result.
- Save wall and CPU results only after the work finishes; eligibility uses host samples and completeness, never wall time, CPU consumed by the benchmark, revision, or direction of the observed delta. Report medians and all paired ratios; n=3 cannot establish a reliable population p95. Preserve the original >10% profiling trigger and all disclosed short-operation costs.

The authorized implementation checks are syntax and pure-data eligibility fixtures only. The root will start actual indexing after independent source review and after its verification jobs and other owned workloads finish. A successful collector run means three eligible healthy pairs were collected; it does not itself declare a performance pass.
